## 当前可运行版本 🪟

仓库中的 Windows 单文件程序位于 [dist/Grounder.exe](dist/Grounder.exe)。双击即可启动，包内包含 Python 运行时和 Node.js 24.14.0。

程序只读取本地保存的登录凭证和运行日志。程序不会修改 Windows 系统代理，不会安装证书，不会拦截微信流量，也不会请求管理员权限。

登录时可粘贴本人凭证，或填写 HAR / JSON 会话文件路径。程序验证账号和包场人成功后才保存凭证。

凭证、微信提醒设置、运行日志和提交记录保存在 `%LOCALAPPDATA%\TennisBooking`。已有 `src/assets/config.json` 配置仍可读取。HAR 只提取 `https://jsapp.jussyun.com/jiushi-core/` 请求中的 token，JSON 支持 `{"token":"本人凭证"}` 或久事 session.json 格式。

## 从源码运行和打包 🔧

源码运行需要 Python 和 Node.js。在仓库根目录执行以下命令安装依赖并运行源码：

```powershell
python -m pip install -r requirements.txt
python src\__main__.py
```

生成 Windows 单文件程序需要额外安装 Nuitka：

```powershell
python -m pip install Nuitka
powershell -ExecutionPolicy Bypass -File tools\build_release.ps1 -Python .venv\Scripts\python.exe
```

打包脚本会带上本机 Node.js 可执行文件和匹配的许可证。Node.js 24.14.0 的许可证已保存在 `tools/licenses`，其他版本可通过 `-NodeLicense` 指定。发布文件写入 `dist\Grounder.exe`。

运行 `dist\Grounder.exe --check` 可检查包内 JavaScript 执行环境。

## 使用说明 🛠️

订场流程设计见 [docs/booking-flow.md](docs/booking-flow.md)，久事第一阶段流程见 [docs/jiushi-first-flow.md](docs/jiushi-first-flow.md)。后续只在本仓库维护，AutoOrder 不再作为开发入口。

### 1. 安装依赖 📦

1. 双击 `dist\Grounder.exe`，默认控制台和 Windows Terminal 均可使用
2. 小窗口中可滚动查看表单，备选方案和查询设置可以展开
3. 准备本人久事凭证或 HAR / JSON 会话文件，用登录弹窗验证账号

### 2. 登录 🔐

<img align="center" src="src/assets/log_in.png">

点击「登录 / 更新凭证」，在弹窗粘贴本人凭证，或点「选择会话文件」选择 HAR / JSON 文件。程序验证账号后读取包场人，失败时保留已保存凭证。当前版本仍需要用户自行准备凭证文件，获取和更新会话的普通用户体验还在完善中。

> 注意, 在手机或者其他地方再次打开小程序会使 token 失效，需要重新登录

### 3. 订场 🏟️

1. 登录之后选择包场人信息
2. 选择运动之后，选择场馆
3. 点击「选择候选场次」，选择可接受的场地和时间范围，点击「确定」
    <img align="center" src="src/assets/select.png">
4. 配置主方案和备选方案，可以选择单个场次、同场连续场次或不连续组合
5. 点「查询候选」查看当前匹配结果，设置预算、立即开始或今天定时、查询次数和查询间隔
6. 点「开始预定」，核对场馆、候选时段、方案和预算，再确认开始。执行时检查官方开放日期和实时库存，按方案顺序提交首个匹配方案
7. 匹配后重新检查开放日期、库存、价格和已有订单，再提交一次。提交后通过官方详情核对场馆、场次和金额，确认订单后进入付款跟踪
8. 打开久事体育 → 我的订单 → 待支付，核对后付款。程序每 15 秒查一次官方付款状态，最多跟踪 30 分钟。点「停止」或退出会结束本轮跟踪，订单记录保留

### 微信提醒

在顶部点击「微信提醒」，填写 Server酱 Turbo 的 SCT SendKey，点「保存并测试」。已有密钥可留空并重新测试，服务接受消息后请在微信确认接收。

设置使用当前 Windows 用户加密保存。官方订单详情核对成功后发送付款提醒，包含官方付款期限。发送失败会在日志提示，最多重试三次，每次至少间隔 30 秒。提醒中不包含登录凭证和包场人信息。

### 订单与付款

在顶部点击「订单 / 付款」，选择待核对或待付款记录，点「继续核对 / 跟踪」。界面显示官方付款状态和期限，可以随时停止。跟踪过程只读取官方订单。

提交超时或结果不明时会保留核对目标和提交前订单快照。重新打开记录后继续寻找唯一匹配新订单，确认后进入付款跟踪。旧版记录如果没有保存完整目标，会提示直接到久事官方核对。

### 当前验证范围

24 项回归测试覆盖 HAR 来源筛选、旧配置读取、失败导入保留凭证、预算内候选、大量不连续候选、连续性、备选方案、未开放日期禁止提交、结果不明防重复、官方详情核对、付款状态及提醒去重。80×25、120×40 和 140×45 界面检查通过，包含文件选择、候选切换日期保留勾选、方案数量和订单弹窗。本机旧会话已通过只读请求确认失效，真实新会话登录、真实订单付款及微信送达仍待验收。

> 注意：
> 1. 不要抢最后一天的场地，最后一天的场地是不开放预定的，显示已订的是场馆内定预留的
> 2. 不要把开抢时间设置在官方设定的开抢时间(羽毛球是中午 12 点)之前
> 3. 不要把重试间隔设置得很短，一般不需要改动，适当增加重试次数即可
> 4. 存在被久事体育封号风险，尽量使用小号
