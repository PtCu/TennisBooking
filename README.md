> 本仓库基于 [XIGUAjuice/Grounder](https://github.com/XIGUAjuice/Grounder) 与 [PtCu/TennisBooking](https://github.com/PtCu/TennisBooking) 的个人改造版。
> 与上游最大的不同：**不装证书、不设系统代理**，直接从正在运行的电脑微信内存里读取登录态；选场支持**涂色分组**多方案备选；抢不到时自动转入**候补捡漏**。

## 主要特性 ✨

| 能力 | 说明 |
| --- | --- |
| 免代理登录 | 直接读电脑微信「久事体育」小程序的登录态，通常 3 秒内完成，无需安装证书、无需改系统代理 |
| 涂色分组多选 | 4 支画笔（①首选 ②③④备选）给场地格子涂色：**同色＝同一笔订单打一起**，**不同色＝备选优先级**，按 ①→②→③→④ 依次抢，抢中即停 |
| 智能配组 | 填「时段 + 预算」一键自动圈选：优先挑同场地连续 2 小时黄金档，预算不够自动降级为单小时，全部售罄则自动转为候补盯防池 |
| 12306 式候补 | 抢不到（或直接盯已售罄的场次）时每 3.5～7 秒随机刷新一次场地状态，一旦有人退场释放立即自动下单 |
| 微信提醒 | 下单成功自动查询订单号与付款截止时间，通过 Server酱（ServerChan）推送到你的微信 |
| 演练模式 | 全程生成真实加密载荷但不真实提交，用来验证流程与时间点 |

## 环境要求 📦

1. **Windows 10 / 11**（内存读取依赖 Win32 API）
2. **电脑版微信**，并已登录、打开过「久事体育」小程序
3. **Node.js**（生成下单签名 `type__1754` 需要）
4. **Python 3.12+**（仓库内 `start.cmd` 会优先使用 `.venv\Scripts\python.exe`）
5. 建议用 **Windows Terminal** 运行：`start.cmd` 会自动调用它，可避免老版 `conhost.exe` 在高频刷新时崩溃

首次使用安装依赖：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 快速开始 🚀

双击仓库根目录的 **`start.cmd`** 即可（它会切到 Windows Terminal 并调用 `.venv` 里的解释器）。
也可以手动执行：

```bat
.venv\Scripts\python.exe src\__main__.py
```

界面从上到下分三块：**用户信息**、**场馆预定**、**日志**。

## 1. 登录 🔐

启动后会自动尝试登录，也可以随时点「登录」重新读取。

1. 保持电脑微信登录着，先把「久事体育」小程序打开过一次；
2. 点「登录」，程序自动从微信进程内存里读出有效 token（通常 3 秒内）；
3. 成功后状态显示 ✅ 已登录，并自动拉取用户名下的**包场人信息**（可下拉切换）。

> ⚠️ 久事体育是单端登录：**只要你在手机或其他设备上再打开一次小程序，电脑端的 token 就会失效**（日志会提示 401 / Token 已过期）。
> 解决办法：在电脑微信里把「久事体育」小程序点进「场馆」页刷新一下，然后回到 Grounder 点「登录」。

## 2. 选场地：涂色分组 × 智能配组 🏟️

选好「运动 → 场馆」后点「选择场地」，会弹出按天分页的场地网格。

### 2.1 涂色规则（核心）

| 操作 | 含义 |
| --- | --- |
| 同一颜色涂多个格子 | **同一笔订单一起下单**（例如同一片场地连着订 19:00 + 20:00） |
| 不同颜色分别涂（①→②→③→④） | **备选方案**：按 ①→②→③→④ 顺序逐个尝试，**抢中任一组立即停止** |
| 给「已订」的格子涂色 | 该格子变成**候补盯防目标**，等别人退场后自动抢 |
| 再点一次已涂色格子 | 取消该格子的颜色 |

- 顶部 4 支画笔可鼠标点选，也可直接按键盘 **`1` `2` `3` `4`** 切换当前画笔；
- 网格里 `①¥180` 表示已选进 ① 组、价格 180；`补②` 表示这是 ② 组的候补盯防目标；
- 底部「备选顺序」会实时汇总成 `①[...] → ②[...]`，确认无误点「确定」。

### 2.2 智能配组（不想手挑就用它）

在弹窗顶部填两个值，点「智能配组」：

| 输入 | 说明 | 默认 |
| --- | --- | --- |
| 时段 | 期望打的时段，如 `18:00-22:00` | `18:00-22:00` |
| 预算 | **单组**总价上限（元），留空＝不限 | 不限 |

程序会优先把「同场地连续 2 小时」的黄金场次涂成 ①②③④；凑不满时补充单小时方案；如果这个时段当前全部售罄，会自动把 4 组最佳目标圈成**候补盯防池**，并提示你直接去蹲退票。

> 「清空」可一键清掉当前所有涂色重来。

## 3. 开抢 🎯

主界面第二行只有 3 个按钮，看情况点即可：

| 按钮 | 什么时候点 | 点完之后 |
| --- | --- | --- |
| **定时开抢** | 还没到放票时间（例如 11:55 选好场，等 12:00 放票） | 倒计时等待「开抢时间」，到点自动按 ①→②→③→④ 抢单；放票后全抢空会弹窗询问是否转候补 |
| **立即抢/候补** | 现在就想抢现有余票，或目标本来就是「已订」场次 | 选了可抢的场次就立刻抢；如果选的全是已订场次，直接进入候补盯防 |
| **停止** | 随时想中断等待/抢单/候补 | 立即结束当前任务 |

参数说明（第三行）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 开抢时间 | `12:00:00` | 网球/羽毛球通常在中午 12:00 放票，请按场馆实际放票时间设置 |
| 重试 | `10` | 备选队列整体尝试的轮数 |
| 间隔(ms) | `250` | 每轮之间的基础间隔，不建议设得过低 |
| 偏差(%) | `10` | 间隔的随机抖动，用来避免固定节奏的高频请求 |
| 预算上限 | 不限 | 超过该总价的方案会被自动跳过，防止手滑买贵 |
| 演练模式 | 关 | 打开后只生成真实加密载荷、不真正提交，适合验证流程与时间点 |

> 距离开抢 ≤ 60 秒时，程序会自动从微信内存刷新一次 token，避免关键几秒掉登录态。

## 4. 候补捡漏（12306 式）🕒

可选方案当前全部售罄时：

1. 点「定时开抢 / 立即抢」跑完一轮没抢到 → 弹窗「立即转入候补 / 暂不候补」；
2. 若你选的本来就全是「已订」场次 → 直接开始候补，不再弹窗；
3. 候补期间每 **3.5～7 秒**随机刷新一次场馆状态，按 ①→②→③→④ 顺序检查整组是否全部释放；
4. 整组可约且未超预算 → 立即下单 → 微信提醒你付款；
5. token 中途失效会自动重读一次微信内存续期，续不上会提示你重新登录；
6. 随时点「停止」退出候补。

## 5. 微信提醒（Server酱）📱

1. 打开 [Server酱 Turbo](https://sct.ftqq.com/)，用微信扫码登录并完成绑定；
2. 复制页面上 `SCT` 开头的 **SendKey**；
3. 回到 Grounder，点右上角「**手机提醒**」，粘贴 SendKey 后点「保存并测试」；
4. 手机微信收到测试消息即配置成功，之后抢中会自动推送**场馆、时段、订单号、付款截止时间**。

> SendKey 与登录 token 都保存在 `src/assets/config.json`（已被 `.gitignore` 忽略，不会提交）。

## 常见问题 ❓

| 现象 | 原因与处理 |
| --- | --- |
| 日志提示「Token 已过期 / 401」 | 你在手机端打开过小程序把电脑端踢下线了。电脑微信里点进「久事体育 → 场馆」刷新一次页面，再点「登录」 |
| 「未在小程序渲染进程中找到登录态」 | 电脑微信里还没打开过「久事体育」小程序，或打开后没有进入「场馆」页（没有任何接口请求就不会有 token） |
| 登录没反应 / 卡住 | 已优化为只扫小程序渲染进程，正常 3 秒内出结果；若仍卡住请看日志最后一行提示 |
| 窗口一闪而过或界面花屏 | 用仓库的 `start.cmd` 启动（走 Windows Terminal），不要直接在老 `cmd` 里跑 |
| 抢到提示「预约失败」 | 常见为放票瞬间被抢光、或该日期根本未开放；看日志里的 `rtnMessage` |
| 抢最后一天的场次总是失败 | **最后一天的场地通常不对外开放预定**，显示已订是场馆内定预留，请抢前 7 天内的场次 |
| 弹了滑块验证 | 正常下单走动态签名一般不会触发；偶发触发时会自动用无头浏览器处理，失败则重试下一轮 |

## 注意事项 ⚠️

1. **不要抢最后一天的场地**：最后一天通常不开放预定，显示已订的是场馆内定预留；
2. **不要把开抢时间设在官方放票时间之前**（网球/羽毛球一般是中午 12:00），提前点只会白白消耗重试次数；
3. **不要把重试间隔设得很短**，一般无需改动，适当提高重试次数即可；
4. 久事体育是**单端登录**，抢票期间不要在手机上打开小程序，否则 token 会立刻失效；
5. 存在被平台风控/封号的风险，建议仅在自有账号上小范围使用。
